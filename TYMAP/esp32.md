You are an expert embedded developer. Write the complete firmware for an ESP32‑S3 (N16R8) acting as a motorcycle HUD display. The device receives data from an Android phone over BLE and shows it on a round GC9A01 240×240 SPI display. Use Arduino framework on PlatformIO.

## 1. SYSTEM OVERVIEW

- The ESP32 has 3 display modes: **HUD** (turn arrow, street name, distance, speed, ETA), **MAP** (JPEG image 240×240), and **STATUS** (clock, weather, battery voltage).
- Modes are switched by a physical **MODE button** (GPIO0) using an on‑screen overlay menu.
- Zoom in/out commands (for MAP mode only) are sent by a second **ZOOM button** (GPIO1).
- All navigation data, time, weather, and map JPEG are received via BLE from the Android app.
- The device sends a 1‑byte control command when buttons are pressed, so the phone knows the current mode and zoom requests.

## 2. HARDWARE & PINOUT

- Board: ESP32‑S3 DevKitC‑1, Flash 16 MB, PSRAM 16 MB (enable PSRAM in board config).
- Display: GC9A01, SPI
  - CS = 10, DC = 8, RST = 9, MOSI = 11, SCLK = 12, BL = 14
- Buttons (external pull‑up):
  - MODE_BTN = GPIO0 (short=cycle, long=select in overlay)
  - ZOOM_BTN = GPIO1 (short=zoom in, long=zoom out, only active in MAP mode)
- Battery voltage measurement: ADC1_CH2 (GPIO2) with a 1/6 voltage divider (max input 15V → 2.5V).

## 3. REQUIRED LIBRARIES (PlatformIO)

- TFT_eSPI (configured for GC9A01, 240×240, with custom font support)
- NimBLE-Arduino (lighter than Bluedroid)
- JPEGDEC (for decoding JPEG directly to screen)
- ESP32Time (for software RTC)
- OneButton (for button handling)
- Use PSRAM for large buffers (JPEG accumulation, menu sprite)

## 4. BLE GATT PROFILE

Create a single BLE service (UUID can be random). Implement these characteristics:

## 5. DISPLAY MODES & UI RENDERING

Use TFT_eSPI with a custom font (MyFont, generated by FontMaker) for all text. Define an icon set (icons.h) with 21 icons (64×62 px) stored in PROGMEM.

### 5.1. HUD Mode

- Parse the received `navString` to extract fields.
- Draw the turn icon (using `iconIndex`), street name, distance, speed, and ETA at appropriate positions. Use MyFont.

### 5.2. MAP Mode

- Receive JPEG via CHA_MAP_IMAGE.
- Accumulate data in a PSRAM buffer (max 32 KB). Once the received length equals the header size, call `processJPEG()`.
- **JPEG decoding**: Use JPEGDEC. In the `pdraw` callback, use `tft.pushImage(x, y, w, h, pixels)` to output directly to the display. No full framebuffer needed.
- Map mode does not draw anything else; the JPEG covers the whole screen.

### 5.3. STATUS Mode

- Draw time from ESP32Time (HH:MM).
- Parse weather JSON, draw corresponding weather icon and temperature.
- Read ADC voltage (see section 7), calculate actual battery voltage, and display it (e.g., “12.3V”).

## 6. BUTTON HANDLING & OVERLAY MENU

Use OneButton library for debouncing and click/long‑press detection.

### 6.1. MODE Button (GPIO0)

- **Short click**:
  - If overlay menu is NOT active: create a 240×240 sprite in PSRAM, draw a semi‑transparent background, three large icons (HUD, MAP, STATUS) with labels, and highlight the current mode. Set `menuActive = true`, `menuSelection = currentMode`.
  - If overlay menu IS active: increment `menuSelection = (menuSelection + 1) % 3`. Redraw the highlight.
- **Long click (1 second)**:
  - If overlay menu is active: set `currentMode = menuSelection`, clear overlay, send `CHA_DEVICE_CTRL` with bit2 = 1 if new mode is MAP, else bit2 = 0.
  - If overlay menu NOT active: force mode to HUD (`currentMode = MODE_HUD`), send control byte (bit2=0).
- **Timeout**: if no button activity for 5 seconds while menu is open, close it without changing mode.

### 6.2. ZOOM Button (GPIO1)

- Only process if `currentMode == MODE_MAP`.
- **Short click**: send `CHA_DEVICE_CTRL` with bit0 set (0x01).
- **Long click**: send `CHA_DEVICE_CTRL` with bit1 set (0x02).
- The phone will adjust the map zoom and send a new JPEG.

## 7. VOLTAGE READING

- In STATUS mode, read ADC1_CH2 periodically.
- Convert to voltage: `V_adc = analogReadMilliVolts(pin) / 1000.0; V_battery = V_adc * 6.0;` (since divider is 1/6).
- Display as a string.

## 8. MAIN FIRMWARE STRUCTURE

File organization:

- `main.cpp`: setup, loop
- `ble_manager.cpp/h`: BLE server, characteristic callbacks
- `jpeg_handler.cpp/h`: JPEG accumulation and decoding
- `mode_manager.cpp/h`: button handling, overlay menu, state machine
- `ui_renderer.cpp/h`: draw functions for HUD, STATUS
- `icons.h`: PROGMEM icon data

**setup()**:

- Initialize TFT (set rotation, fill black, backlight on), PSRAM check.
- Initialize BLE server.
- Configure OneButton instances.
- Configure ADC for battery.
- Initialize ESP32Time.

**loop()**:

- Call `button.tick()` for both buttons.
- Call `updateTime()` every second (for STATUS).
- Handle any new data flags set by BLE callbacks:
  - If new HUD data → if in HUD mode, redraw.
  - If new weather → if in STATUS, redraw.
  - If new JPEG → if in MAP mode, decode.
- Redraw STATUS every second if in that mode.
