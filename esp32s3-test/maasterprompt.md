## 1. SYSTEM OVERVIEW

```
[ESP32‑S3 + GC9A01] <─── BLE ───> [Android App] <─── Internet ───> [Free APIs]
```

- The **Android app** is the brain: it handles GPS, routing, map rendering, weather, voice, and sends processed data to the ESP32.

## 2. ESP32‑S3 HARDWARE & PINOUT

- Board: ESP32‑S3‑DevKitC‑1, Flash 16 MB, PSRAM 16 MB (enable PSRAM in board config).
- Display: GC9A01 1.28″ round 240×240, SPI:
  - CS = 10, DC = 8, RST = 9, MOSI = 11, SCLK = 12, BL = 14
- Buttons (external pull‑up):
  - MODE_BTN = GPIO0 (short=cycle overlay menu, long=select)
  - ZOOM_BTN = GPIO1 (short=zoom in, long=zoom out; only active in MAP mode)
- Battery voltage measurement: GPIO3 (ADC1_CH2) via voltage divider R1=100kΩ, R2=27kΩ. Add a 100 nF capacitor from GPIO3 to GND and a 3.3 V Zener diode for protection.

## 3. ESP32‑S3 FIRMWARE (PlatformIO / Arduino)

### 3.1. Libraries
- **TFT_eSPI** configured for GC9A01, 240×240, custom font support.
- **NimBLE‑Arduino**
- **JPEGDEC** (decode JPEG directly to screen, no full framebuffer)
- **ESP32Time**
- **OneButton**
- Use PSRAM for JPEG buffer (max 32 KB) and menu sprite (240×240).

### 3.2. Font & Icons
- Font: `MyFont` generated by [FontMaker](https://github.com/daonguyen207/FontMaker).
- **Turn‑by‑turn icons** (detailed in Section 3.9).

### 3.3. BLE GATT Profile (Service UUID can be random)
Use these exact characteristic UUIDs and formats.

| Characteristic | UUID | Direction | Format & Usage |
|----------------|------|-----------|----------------|
| CHA_NAV | `0b11deef-1563-447f-aece-d3dfeb1c1f20` | App → ESP | Text: key=value lines separated by `\n`. (e.g., `dist=200m\ninst=Rẽ phải\nroad=Nguyễn Huệ\neta=14:30\nete=5 min`) |
| CHA_NAV_TBT_ICON | `d4d8fcca-16b2-4b8e-8ed5-90137c44a8ad` | App → ESP | **1 byte (0‑20) icon index** (preferred) OR byte array (288 bytes 48×48 1bpp). Default to 1‑byte index. |
| CHA_GPS_SPEED | `98b6073a-5cf3-4e73-b6d3-f8e05fa018a9` | App → ESP | Text: integer km/h (e.g., `60`) |
| CHA_SETTINGS | `9d37a346-63d3-4df6-8eee-f0242949f59f` | App → ESP | Text: key=value (e.g., `brightness=80\nspeedWarning=1`). Sent on connect and on changes. |
| CHA_TIME | `a1b2c3d4-e5f6-4789-a012-3456789abcde` | App → ESP | 4 bytes little‑endian uint32 Unix timestamp. Sent on connect & every 5 min. |
| CHA_WEATHER | `b2c3d4e5-f6a7-4890-b123-456789abcdef` | App → ESP | JSON: `{"t":30.5,"i":"01d"}`. Sent every 10 min. |
| CHA_MAP_IMAGE | `c3d4e5f6-a7b8-4901-c234-567890abcdef` | App → ESP | First 4 bytes: little‑endian uint32 JPEG size, then JPEG byte stream. Sent only when ESP32 Map mode active. |
| CHA_DEVICE_CTRL | `d4e5f6a7-b8c9-4012-d345-678901bcdef0` | **Bidirectional** | 1 byte bitfield: bit0=zoom in, bit1=zoom out, bit2=Map mode on/off, bit3=request refresh. ESP sends on button press; app can also send for manual zoom. |
| CHA_REMOTE_CMD | `f1a2b3c4-d5e6-4789-a012-3456789abcde` | App → ESP | 1 byte command: `0x10`=HUD, `0x11`=MAP, `0x12`=STATUS, `0x20`=Request status, `0x30`=Ping, `0xFF`=Restart |
| CHA_DEVICE_STATUS | `a1b2c3d4-e5f6-4789-b012-3456789abcde` | ESP → App | Text key=value: `mode=HUD\nvoltage=12.3\nrssi=-45\nping=ok`. ESP updates periodically or on request. |

### 3.4. Display Modes & UI

#### HUD Mode
- Parse `CHA_NAV` text (key=value) into a `NavigationData` struct.
- Draw the turn icon (from PROGMEM, index from `CHA_NAV_TBT_ICON`), street name, distance, speed, ETA using `MyFont`.

#### MAP Mode
- Accumulate JPEG data from `CHA_MAP_IMAGE` in a PSRAM buffer (32 KB).
- When received size == header size, call `JPEGDEC.openRAM()` with a `pdraw` callback that uses `tft.pushImage(x, y, w, h, pixels)`. No full frame buffer needed.
- The JPEG covers the whole screen.

#### STATUS Mode
- Draw time from `ESP32Time` (updated every second).
- Parse weather JSON, draw corresponding weather icon and temperature.
- Read battery voltage via ADC1_CH2, calculate actual voltage (multiply by divider ratio), display.

### 3.5. Overlay Menu (MODE Button)
- Short click: if menu not active, create a 240×240 sprite in PSRAM, draw semi‑transparent background, three large icons (HUD, MAP, STATUS) with labels, highlight current mode. Set `menuActive = true`.
- Short click while menu active: cycle `menuSelection`.
- Long click (1 s): if menu active, set `currentMode = menuSelection`, close overlay, send `CHA_DEVICE_CTRL` (bit2=1 for MAP, else 0). If menu not active, force HUD.
- Timeout 5 s: close menu without change.

### 3.6. ZOOM Button
- Only active in MAP mode.
- Short click: send `CHA_DEVICE_CTRL` with bit0 (0x01).
- Long click: send `CHA_DEVICE_CTRL` with bit1 (0x02).

### 3.7. Remote Commands (CHA_REMOTE_CMD)
- `0x10‑0x12`: change mode.
- `0x20`: send status update via `CHA_DEVICE_STATUS` (mode, voltage, RSSI).
- `0x30`: respond with `ping=ok` in `CHA_DEVICE_STATUS`.
- `0xFF`: call `ESP.restart()` after a short delay.

### 3.8. OTA (Placeholder)
- Include a stub function `checkForOTA()` and a characteristic placeholder, referencing the OTA mechanism of [chronos-esp32](https://github.com/fbiego/chronos-esp32) for future implementation.

### 3.9. Turn‑by‑Turn Icon Set (Detailed)
The firmware must include a complete set of 21 navigation icons stored in PROGMEM (file `icons.h`). Each icon is 64×62 pixels, 1‑bit per pixel (black and white) or RGB565.

| Index | Name | Description (visual) |
|-------|------|----------------------|
| 0 | Straight | Up arrow ↑ |
| 1 | Slight right | Curved arrow gently right ↗ |

#### 3.9.2. Icon Data Format
- Each icon is a byte array, e.g. `const uint8_t icon_0[] PROGMEM = { ... };`
- All arrays are stored in a pointer array: `const uint8_t* const icon_array[21] = { icon_0, icon_1, ..., icon_20 };`
- Drawing function:
```cpp
void drawIcon(int index, int x, int y) {
    tft.drawBitmap(x, y, icon_array[index], 64, 62, TFT_WHITE, TFT_BLACK);
}
```
- In HUD mode, call `drawIcon(iconIndex, x, y)` with the index received from the phone.

#### 3.9.3. Generation Tool
- Icons can be created using any drawing tool (64×62 px, black on white background).
- Convert to C array using [image2cpp](https://javl.github.io/image2cpp/) or similar.

### 4.8. Share Handling & UrlParser
**UrlParser.kt** (domain layer, no Android dependencies except OkHttp):
- Data class `GoogleMapData` (type: POI, ROUTE, UNKNOWN; destinationLat/Lng; optional originLat/Lng).
- `extractUrlFromText(input: String): String?` – regex `https?://[^\\s]+`.
- `suspend resolveRedirect(shortUrl: String): String?` – OkHttp with `followRedirects(false)`, HEAD request, return `Location` header on 301/302/303/307.
- `parseCoordinates(expandedUrl: String): GoogleMapData` – try 3 regex patterns in order:
  1. Route: `/dir/(-?\d+\.\d+),(-?\d+\.\d+)/(-?\d+\.\d+),(-?\d+\.\d+)`
  2. POI @: `@(-?\d+\.\d+),(-?\d+\.\d+)`
  3. POI q=: `[?&]q=(-?\d+\.\d+),(-?\d+\.\d+)`
- Extension `GoogleMapData.toOsmUrl(): String?` – convert to OSRM format (Lng,Lat;Lng,Lat).

**ShareReceiverActivity**:
- Receive `ACTION_SEND`, call `extractUrlFromText`.
- If short link, call `resolveRedirect`.
- Call `parseCoordinates`.
- If coordinates found, pass to `MapFragment` (via Intent or `NavigationRepository`) to drop pin.
- If type == UNKNOWN, call Photon (primary) then Nominatim (fallback) to geocode the place name.
- If all fail, show Toast "Location not found".
